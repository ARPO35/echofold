# 评审决策清单

## 1. 已确认的产品与技术决策

| 主题 | 决策 | 状态 |
|---|---|---|
| 前端 | Flutter 负责三页 UI、滚动与动画 | 已确认 |
| 原生边界 | Android 原生负责持续 PCM 采集、AAC 编码和本地 ASR | 设计定稿，待尖刺 |
| ASR 路由 | 仅本地，无远端 ASR | 已确认 |
| ASR 模型 | X-ASR 480ms 单模型候选；实际 INT8 工件/转换须固定 revision/hash，SenseVoice 仅基准对照 | 路线已确认，工件与质量待预注册实测决策 |
| ASR 过载 | p95 落后正常目标 ≤15 秒；超过跳读线插入不可变 GAP `...` 并跳至最新音频 | 已确认，待实现与故障测试 |
| 重识别 | 所有文本段/GAP 可长按重识别；同一本地模型和会话固定版本，可离线；成功新增版本，不覆盖原始证据 | 已确认 |
| 模型分发 | 权重不进 APK，签名清单下载/导入、校验、防回滚、更新、回滚；活动租约与 `pending-delete` | 已确认 |
| LLM | OpenAI-compatible BYOK，手机直连，无中继；默认 HTTPS，跨域重定向禁止转发 Authorization | 已确认 |
| 离机数据 | 仅稳定文字和必要上下文；音频不上传 | 已确认 |
| 使用边界 | 用户显式会话，后台继续，不做隐蔽全天候常驻 | 已确认 |
| 音频格式 | AAC-LC/M4A、单声道、目标 192kbps | 已确认，设备能力待测 |
| 音频分块 | 默认 60 秒，暂停/结束封块，导出时合并；先持久化原子占位再初始化编码器 | 设计定稿，30/60/300 秒待对比 |
| 音频时间域 | UTC 创建/封存、单调采集时间和实际内容 offset 分开；暂停间隙不计入回听位置 | 已确认 |
| 有界队列与音频 | 采集/ASR/AAC/持久化/UI/LLM/重识别/导出队列有界；正常录制零静默丢失 | 已确认 |
| 音频保留 | 默认长期保留，空间不足永不自动删除 | 已确认 |
| 左滑结束 | 实际位移阈值；保存旧会话并新建空闲会话，不自动录音 | 已确认 |
| 阅读层级 | L1 校订全文、L2 段落要点、L3 会话摘要，L0 独立证据 | 已确认 |
| 预处理 | FINAL 足够成段立即开始，不等折叠时间 | 已确认 |
| 折叠计时 | `foldDueAt=max(sourceFinal.finalizedAt)+当前配置延迟`；配置变化重算未到期段，已到期不重置；迟到结果就绪即折叠 | 已确认 |
| 多源身份 | `sourceFinalIds[]`/`sourceVersions[]` 有序，规范化 `sourceSetHash` 用于请求、回显、缓存和提交 | 已确认 |
| 手动展开 | 当前会话 `ReaderContext` 内不再自动收起；三页切换保持，换会话或进程重启清除；双击解除 | 已确认 |
| 自由阅读 | 其他段仍到期折叠，顶边锚定 | 已确认 |
| 编辑 | 修改 L1 用户版本，L0 不可变，下游过期重建 | 已确认 |
| 回听冲突 | 录音中要求用户先手动暂停，应用不自动改变状态 | 已确认 |
| 标题 | 自动生成；未 revealed 的最新有效版本继承首次展示资格，第一次实际可见动画一次；revealed 后普通更新 | 已确认 |
| 动画 | 弹簧与短缓动、可打断、继承速度、尊重减少动态效果 | 已确认 |

## 2. 30 分钟可行性尖刺必须回答的问题

以下问题是技术可行性检查，不是发布通过声明；两台参考设备分别记录，未测项标“待测”。

- [ ] 实际 X-ASR 工件/revision/SHA-256、INT8 来源或转换链是否完整？未证实的约 134MB/169MB 是否已从预算排除？
- [ ] 数据集 manifest、参考转写、CER/WER 评分器和试点是否可复现？最低 CER/WER 上限是否将在模型决策和 1.5 前冻结？
- [ ] 持续 `RTF < 1`、p95 ASR 落后 ≤15 秒及冻结后的准确率门槛能否同时满足？语义正确性是否未被速度降级牺牲？
- [ ] sherpa-onnx 的 Android 集成能否稳定提供所需时间戳和中英混合能力？超 15 秒时 GAP/跳至最新音频和离线重识别是否可行？
- [ ] AudioRecord→ASR/AAC/振幅三路分发及所有持久化队列是否始终有界？占位/封存失败是否真实暴露且音频不静默丢弃？
- [ ] 目标设备实际 AAC 192kbps 支持情况如何？偏差如何呈现，正常封存空间预留是否有效？
- [ ] 在相同条件下比较 30/60/300 秒分块后，恢复损失、文件数、封装开销和恢复时间分别是多少？
- [ ] Media3 合并是否可无损转封装，块边界是否出现爆音、重叠或异常静音？
- [ ] Flutter/Kotlin 事件通道在频繁 Partial 下是否稳定？两小时发布长测须另行回答长时稳定性。
- [ ] BYOK 目标端点支持哪种 structured output？HTTPS、跨域重定向去 Authorization、无效响应与失败兼容性如何？

## 3. 实现与发布前出口

- [ ] 产品决策无未标注冲突，尤其不得重新引入远端 ASR、第二识别模型、自动删除旧音频或左滑自动录音。
- [ ] 30 分钟尖刺报告附真实配置、工件哈希和失败样例，不将作者基准或官方示例 RTF 当手机实测；未证实大小不作预算。
- [ ] 模型选择前已冻结精确工件/转换、manifest/评分器和全部数值预算；试点后、1.5 前的最低 CER/WER 门槛是 go/no-go 前置。
- [ ] 数据 schema、迁移、幂等键、有序来源/sourceSetHash、音频三时间域、原子块占位和所有状态转换评审通过。
- [ ] ASR GAP/重识别、所有有界队列、音频零静默丢失、ReaderContext 生命周期和标题继承均有实现任务与可测试场景。
- [ ] 模型租约/pending-delete、HTTPS 默认与跨域重定向不转发 Authorization 有契约测试。
- [ ] 手势与滚动原型通过快速短甩、慢速过阈值、动画中断和标题重启恢复测试。
- [ ] 人工语义支持规则、双评审/裁决和冻结质量门槛可执行，不以“基本准确”等形容词放行。
- [ ] 完整故障矩阵与两台参考设备的两小时发布长测分开完成，任何尾部损失按预注册预算和区间单独判定。
- [ ] 依赖许可、模型许可、隐私与录音授权提示评审通过。

## 4. 仍属后续而非首版阻塞的扩展

- 说话人分离、翻译、问答、云同步和协作。
- 本地 LLM、自部署中继和更多 ASR 模型正式支持。
- 更细的五级 TextFold 式阅读层。
- 第二模型或远端 ASR 补转写不属于已确认的重识别；首版只实现同一本地模型、会话固定版本的离线重识别。
