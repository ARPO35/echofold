# 评测与验收

## 1. 测试原则

- 所有速度、准确率、功耗和稳定性结果都绑定设备、OS、精确模型工件与 revision/SHA-256、量化转换、线程、音频集、评分器和温度条件。
- 模型作者基准、官方示例/第三方测试和本项目实测分栏呈现，不混为同一基准。未证实的约 134MB/169MB 不得进入下载、存储或内存预算。
- **正常录制音频零静默丢失、证据不覆盖、引用不越界、秘密不泄露**是关键出口，不能用平均性能抵消。显式 GAP 只表示 ASR 跳过区间，不表示音频可以丢弃。
- 30 分钟可行性尖刺只回答关键技术能否继续，不替代至少两小时的发布长测；两者使用独立报告和出口，失败不得隐藏降级。
- 数值门槛在模型选择和相应测试开始前冻结；试点数据只用于制定门槛，不作为最终通过证据。尚未测得的数据必须标记为“待测”，不能补写成实测。

## 2. 参考设备、数据集与预注册门槛

至少固定一台中端和一台较低配置 ARM64 Android 参考设备。报告逐台记录设备型号、SoC、RAM、OS 与补丁、厂商电池策略、可用存储、环境温度、供电状态、线程和运行时版本；不得用一台设备的结果代替另一台。

冻结音频集并生成不可变 manifest，逐项记录样本 ID、来源与许可、文件 SHA-256、时长、采样率、类别、说话人/口音标签、参考转写 revision 及哈希。冻结 CER/WER 评分器版本、文本规范化规则、执行命令和计时方法。试点集与最终验收集分开，任何变更都生成新 manifest 版本，不能原地改变历史结论。

| 类别 | 内容 | 目的 |
|---|---|---|
| 中文清晰 | 单人朗读、讲座 | 基础字错率、标点和延迟 |
| 中英混合 | 技术讨论、产品会议 | 术语与中英切换 |
| 噪声 | 街道、风扇、远场 | VAD、错识别和恢复 |
| 多口音 | 不同中文口音 | 模型适用边界 |
| 长会话 | 两小时以上连续材料 | RTF、热稳定、队列与存储 |
| 静音/停顿 | 长静音、频繁短句 | 分块、暂停、端点和空摘要 |

模型 go/no-go 决策前必须完成并签署预注册记录：

1. 固定实际模型文件名、来源、精确 revision、SHA-256、字节数、运行时/ABI；若需 INT8 转换，同时固定源工件、量化工具与版本、命令、校准/配置输入和输出哈希。作者基准不等于转换后或手机实测。
2. 先运行冻结试点，按设备、类别和总体分布确定**最低可接受准确率对应的 CER/WER 上限**，逐指标记录数值、样本范围和置信/失败情况，再冻结为模型选择及 1.5 的前置门槛。本文不凭空给出错误率数值；冻结前模型质量结论只能是“待决策”，不得以“准确度还可以”放行。
3. 速度门槛预注册为两台参考设备各自持续 `RTF < 1`；这是实时必要非充分条件。正常目标为 p95 ASR 落后不超过 15 秒；达到超过 15 秒的跳读条件必须进入显式 GAP 降级，不能以平均 RTF 掩盖。
4. 队列容量、内存增长、温度/功耗观测窗口和异常尾部损失预算均须在相应长测前依据试点冻结为可计算数值；未冻结不得启动最终 go/no-go。指定崩溃故障的尾部损失只在冻结预算内逐项报告，正常录制必须零丢失，故障测试不得默认豁免。

ASR 落后使用会话单调采集时钟计量：对 FINAL 段为音频实际采集结束时间到 FINAL 原子持久化完成时间，并同时报告 oldest-pending-audio 落后以触发过载处理。p50/p95、最大值、样本数和窗口必须同时给出；UI 可见延迟另列，不能混用墙钟、暂停间隙或模型 480ms 块长。

## 3. ASR 指标

| 指标 | 记录方式 | 首版出口 |
|---|---|---|
| CER/WER | 中文以 CER 为主，英文另列 WER；按冻结评分器计算 | 不超过试点后、1.5 前冻结的各项上限；未冻结或无数据即待决策 |
| Partial 延迟 | 从对应音频单调时间到 UI 可见，报告分位数、最大值与样本数 | 使用长测前冻结的预算，不得用形容词放行 |
| FINAL 落后 | 音频实际采集结束到 FINAL 持久化；另记 oldest-pending-audio | 正常目标 p95 ≤ 15 秒；达到跳读线时按 GAP 规则降级 |
| RTF | 推理耗时/输入音频时长，分设备、稳态窗口和温度报告 | 每台参考设备持续 `< 1`，但仅有此项仍不足通过 |
| 重复/缺口 | 与源音频、事件日志和有序来源 ID 对照 | 不得有不可解释重复段；每个跳过区间都有显式 GAP，不得隐藏 |
| 内存/温度/功耗 | 系统采样，报告曲线、峰值、降频和观测窗口 | 不超过长测前冻结预算，队列不得无限增长 |

X-ASR 若不能达标，先调整线程和运行参数，再回到模型评审；不得私自改为远端 ASR 或双模型路线，也不得降低已冻结的准确率上限换取速度。

### ASR 15 秒 GAP 与重识别

- 注入持续慢推理，使 oldest-pending-audio 落后超过 15 秒：阅读流 MUST 插入一行居中的字面量 `...`，停止向旧队列积压并跳到最新音频继续识别。
- GAP 是显式、不可变 L0 段，记录 `reason=ASR_OVERLOAD`、跳过音频的实际采集起止区间、对应块和模型版本；原始证据不可因后续文字或重识别被覆盖。缺口的 `...` 是展示字面量，不参与 CER/WER 分子冒充识别文字。
- 音频采集与 AAC 持久化 MUST 继续；测试同时核对缺口区间仍可回听、无 PCM/AAC 静默丢弃，且非必要 LLM 工作降级。
- 每个文本段及 GAP 段长按均有“重新识别”入口。普通文本段重识别使用其原始音频和来源版本；GAP 段使用记录的跳过区间。均使用会话固定的同一模型工件、revision 和配置，可完全离线执行。
- 成功重识别产生新版本并保留全部父版本/缺口，仅成功且通过校验的版本改变默认展示；失败、取消或重复请求保留原展示，不产生重复有效版本。
- 重识别属于同一模型的离线补救，不得引入第二模型、远端 ASR、网络请求或自动覆盖 L0。报告重识别耗时、成功率、CER/WER、失败样例和离线证明，不承诺未测数值。

## 4. 音频、分块与有界队列

- 验证目标 AAC-LC/M4A、单声道、192kbps 的设备支持和实际参数记录；正常封存必须预留空间，不能在空间耗尽后伪装成功。
- 检查 60 秒自动块、暂停/继续块、结束块和异常块，序号无冲突。逐块核对 UTC 创建/封存时间、`captureStartedMonoNs/captureEndedMonoNs` 与 `capturedStartMs/capturedEndMs`；后者只表示实际采集内容 offset，不包含暂停间隙。
- 新块切换 MUST 先停止向 ASR/AAC 分发新 PCM，原子持久化唯一 `chunkSeq`、临时路径和 `PLACEHOLDER/BLOCKED` 状态，再初始化编码器并恢复分发。占位事务失败时 MUST NOT 继续伪装录音；测试故障点覆盖事务前、事务中、提交后与编码器初始化。
- `OPEN` 只接收当前块数据；`SEALING` 停止接收并冲刷封装；`SEALED` 可独立解码；`SEAL_FAILED` 明确资源失效与尾部损失；`RECOVERABLE` 仅在可验证修复后转为 `SEALED`，否则为 `CORRUPT`。分别验证可安全续录和必须停止的情况，禁止把失败块当正常块。
- 采集、重采样/ASR、AAC 编码、文件持久化、事件投递、LLM/重识别/导出队列全部有界，记录容量、入队/出队、 oldest age、拒绝/合并原因和峰值。音频队列满、写盘慢或封存失败必须进入可见阻塞/失败状态，不得静默丢弃 PCM 或仍显示正常录音。
- 正常录制的 PCM 采集计数、AAC 可解码样本时长、块时间区间和事件日志必须可对账，做到音频零静默丢失；任何差异都是阻塞缺陷。只有明确命名的崩溃故障可产生尾部损失，并须落在预注册量化预算内、标记区间和原因，不得默认放行。
- 在相同设备、音频、编码参数和故障注入下比较 30/60/300 秒分块，报告异常尾部损失、文件数、封装开销、切换停顿、恢复时间和存储需求。默认 60 秒不能代替比较数据，也不能先宣称最优。
- 逐块解码并核对会话时长、采样率、校验和与 ASR/GAP 引用。导出合并后检查可播放性、时长、边界爆音/静音和是否发生非必要重编码。
- 低存储时先安全封存再暂停，旧音频零自动删除；导出失败源块不变。

## 5. 校订、折叠与摘要

建立带人工参考的段落集，覆盖同音错字、口头重复、数字、人名、否定、行动项和中英术语。冻结样例、提示词/模型版本、评分表和判定指南后再验收；报告分歧与失败样例，不能只让模型自评。

### 人工语义支持判定规则

1. 至少两名评审独立按原子事实判定，分歧由第三人按同一指南裁决；记录评审 ID、版本和逐条结果。发布前冻结所需样本量、最低支持率/引用覆盖率和严重错误零容忍项，不能用“基本准确”“大体相关”等不可测形容词代替。
2. 将每条输出拆为独立事实性陈述。只有引用的源文字明确表达该事实，或可由明确表达直接等价改写，才记为“支持”；需要补充常识、跨来源猜测或扩大范围才能成立即记“不支持”。
3. 数字、单位、时间、人名、专有名词、否定/条件、因果、主体与行动关系任一改变，均记为语义错误；仅修正明显同音错字、标点或口头重复且不改变含义才可接受。
4. 每个独立事实性陈述至少一个范围内且语义支持的引用；只有合法 ID 但文字不支持，不算有效。L3 可由已验证 L2 支持，但仍须能回溯 L1/L0。标题按同一来源规则判定主题支持，不另设主观放行。
5. 无来源事实、数字/否定/行动关系改变、用户版本被后台覆盖或 L0/GAP 被覆盖均为阻塞缺陷；不得以平均得分抵消。

| 指标 | 检查 |
|---|---|
| 事实保持 | 按上述人工规则检查 L1/L2/L3，不新增无依据事实 |
| 修改可追溯 | ASR/AI/USER/GAP 版本有父版本与有序来源，L0 永不覆盖 |
| 多源身份 | `sourceFinalIds[]`、`sourceVersions[]` 保持规范顺序，`sourceSetHash` 可重算；请求、回显、缓存和提交逐项一致 |
| 引用有效 | L2/L3 引用存在、落在输入范围且按人工规则支持对应事实 |
| 引用覆盖 | 每个独立事实性陈述至少一个语义有效引用 |
| 折叠时钟 | `foldDueAt=max(sourceFinal.finalizedAt)+当前配置延迟`；配置变化只重算未到期段，已到期不重置 |
| 摘要回退 | 生成失败保留 L1/FINAL/GAP，不出现空白折叠 |
| 标题相关 | 来源明确支持主题，来源变化后可重建，不泄露密钥 |
| 局部重建 | 单段编辑或重识别只影响依赖产物，旧任务不覆盖用户版本 |

## 6. 交互与动画测试矩阵

| 场景 | 预期 |
|---|---|
| 默认新内容追加 | 锁定底部，最新内容可见 |
| 手指按下/用户滚动 | 立即自由阅读，取消程序滚动，显示回底 |
| 手动划到底/点击回底 | 恢复跟随，按钮隐藏 |
| 跟随底部展开 | 向上展开，底边稳定 |
| 跟随底部折叠 | 上至下收起，不把最新内容提走 |
| 自由阅读展开 | 向下展开，顶边/阅读项稳定 |
| 自由阅读其他段折叠 | 下至上收起，阅读位置经补偿稳定 |
| 慢速左滑过阈值 | 封存旧会话，新建空闲会话，不自动录音 |
| 快速短距离甩动 | 不结束，继承速度回弹 |
| 动画中相反操作 | 从当前位置和速度接续，无跳变 |
| 单击/双击/长按竞争 | 只提交一个语义操作 |

| 进程重启 | 清除内存 `ReaderContext`；仅持久化内容/标题展示状态按各自规则恢复 |

| 录音中长按回听 | 只提示先手动暂停，不自动改变状态 |
| 减少动态效果 | 无过冲和非必要位移，功能完整 |

测试不同屏幕尺寸、系统字体缩放、60/120Hz、横竖屏（若支持）和 TalkBack 基本导航。

## 7. 标题首次可见

1. 条目可见时生成：动画一次，完成后写 `revealedAt`。
2. 条目不可见时生成：不提前消费；第一次可见才动画。
3. 尚未 revealed 时产生更新的有效标题版本：最新版本继承 `pendingFirstReveal` 和首次展示资格，旧版本不得抢先消费或覆盖；第一次实际可见展示最新有效版本。
4. 动画中离开或杀进程：状态未提交，下次重播至完成；重启后读到待展示状态。
5. 已完成后重启、列表重建、切换底部页面：不重播；revealed 之后的编辑或自动更新均为普通更新，不重新获得首次展示资格。
6. 标题提交检查有序来源版本和 `sourceSetHash`，旧版本结果不得覆盖新来源。

## 8. 可靠性、安全与完整故障矩阵

下表是最低覆盖集，每一行都须在适用层执行自动化测试，并在两台参考设备上执行涉及真实资源的长测/故障注入。除表中明确允许的量化尾部损失外，不得把失败项默认为通过；所有音频损失必须标出实际区间和原因。

| 故障或攻击 | 注入点/组合 | 必须验证的结果 |
|---|---|---|
| 进程被杀、服务被杀、设备重启 | `PLACEHOLDER/OPEN/SEALING`、持久化提交前后 | 恢复可解码块并标记实际损失；不自动无感重启，不重复 chunk/版本 |
| 占位事务失败、临时路径冲突 | 自动分块、继续、新会话 | 新 PCM 保持阻断；不初始化成伪活动块，不显示正常录音；旧块可回听 |
| 编码器初始化/运行失败、muxer 失败 | `OPEN/SEALING` | `SEAL_FAILED` 与资源失效可见；只允许协议判定安全的续录，禁止伪装保存 |
| 恢复成功/校验失败 | 临时文件、数据库与校验和交错 | `RECOVERABLE` 修复后可解码才转 `SEALED`，否则 `CORRUPT`；不静默改名完整 |
| 权限拒绝/撤销、麦克风占用、音频路由变化 | 启动、录音中、继续 | 状态真实且可操作；不伪造 PCM、振幅或保存进度 |
| ASR 慢于实时/崩溃/重复或乱序事件 | 正常、跨块、暂停冲刷 | 超 15 秒显式 GAP；音频继续；仅录音选择清晰；幂等且不覆盖 FINAL |
| 重识别成功/失败/取消/离线/重复请求 | 普通段、GAP、跨块缺口 | 同模型同会话版本；成功新增版本才改变默认展示，失败保留原缺口/文字 |
| 所有队列饱和、写盘慢、事件通道拥塞 | PCM/ASR/AAC/持久化/UI/LLM/重识别/导出 | 队列有界、指标可见；音频不静默丢弃；资源不足进入明确阻塞或失败 |
| 存储预警/硬下限、封存或导出空间不足 | 自动块、暂停、导出 | 预留正常封存空间；不删除旧数据，不提交半成品；恢复后等待用户操作 |
| 断网、DNS/TLS 失败、401、429、超时、限流 | 请求前、响应中、重试/取消 | 录音与 ASR 继续；任务有界退避；鉴权错误不盲目重试 |
| 无效 JSON、schema 错误、越界/不支持引用 | L1/L2/L3/标题及缓存命中 | 有限修复后回退；逐项校验有序来源与 `sourceSetHash`，不默认提交 |
| BYOK 配置 HTTP、HTTPS 同域/跨域重定向 | 首次连接、重试、模型下载 | 默认只接受 HTTPS；跨域重定向绝不转发 `Authorization`，密钥不到非目标主机 |
| 模型下载中断、哈希不符、签名/代数回滚、更新、回滚、删除 | 活动会话/重识别租约、非活动模型 | 当前会话版本固定；无效签名或回滚清单被拒；活动租约模型转 `pending-delete` 而非断供；释放后清理，回滚可验证 |
| 用户编辑、旧任务晚到、重启重复投递 | 多源合并、标题更新、重识别 | 幂等；旧 `sourceSetHash` 不覆盖新版本；用户版本优先 |
| 导出取消/源块损坏、级联删除、活动会话删除 | 临时文件、原子改名、任务运行中 | 源块不变、半成品不标成功；活动数据受保护；密钥/秘密不进入产物 |
| 三页切换、换会话、进程重启、列表重建 | 展开锁定、滚动、标题动画 | `ReaderContext` 按边界保持或清除；待展示标题恢复，已展示标题不重播 |

## 9. 两小时发布出口

- 两台参考设备分别完成至少两小时发布长测，并通过全部冻结的 CER/WER、RTF、p95 落后、资源和队列门槛；30 分钟尖刺结果不得替代。
- 正常录制音频零静默丢失：音频块序号连续、源文件可解码、数据库与文件状态一致，采集/编码/时间映射可对账。指定崩溃尾部损失逐例标记并符合预注册预算。
- 所有队列有界，内存和资源指标符合冻结预算，延迟与健康报告完整；ASR 过载产生可回听、可重识别的显式 GAP。
- LLM 失败不影响音频、ASR、原始文字和缺口；多源引用及 `sourceSetHash` 校验、人工语义支持规则全部执行。
- HTTPS/重定向、模型租约/pending-delete、密钥与隐私场景通过。
- 三页切换、ReaderContext 边界、滚动/折叠和标题首次展示规则无不可恢复错误。
- 所有关键安全、证据、隐私、手势和上述故障矩阵场景通过。
- 使用固定版本 OpenSpec CLI 执行 `validate add-live-semantic-transcript --strict --no-interactive` 通过；结构校验不替代功能或语义验收。
