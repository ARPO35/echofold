# Design

## Context

这是一个持续写入、异步修订、可离线识别的数据流系统，而不是静态笔记页面。音频采集、ASR、UI 与远端 LLM 的速度和可用性不同，任何一环阻塞都可能造成音频丢失、文字重复或阅读跳动。

方案基线为 Android 10（API 29）及以上、Flutter 前端、Kotlin 原生音频与 ASR 链路。targetSdk 在实现时采用最新稳定版本，并重新核对麦克风前台服务和应用商店政策。首版没有业务服务器，ASR 不联网，LLM 由用户自己的 OpenAI-compatible 端点提供。

本设计记录已确认的行为决策，不表示技术尖刺或实施验收已经完成。能力规格、任务和评测文档已同步，并通过固定版本 OpenSpec 严格结构校验；进入实现前，仍须完成预注册冻结、双设备技术尖刺与评审出口。

## Goals / Non-Goals

### Goals

- 音频持久化、ASR 和界面追加在长会话中互不因 LLM 阻塞。
- 不可变证据、用户校订和 AI 产物分离，高层内容可回到有序源文字版本与音频时间。
- 正常录制音频零丢失；指定异常只允许可定位、可量化的尾部损失，不以崩溃为由默认放行。
- 文字一旦足够形成段落就立即预处理，折叠延迟只控制视觉收起。
- ASR 落后时显式标记转写缺口，保留完整音频并允许用户使用同一会话模型手动重识别。
- 复用 Flutter、Android Media、Media3、sherpa-onnx 与成熟 Flutter 包，避免自写通用底层框架。
- 所有持续动画和滚动都可解释、可打断，并尊重系统减少动态效果设置。
- 在断网、崩溃、低资源和模型不可用时保持明确降级。
- 先冻结可复现评测基线，再以语义正确性为门槛选择速度更快的模型配置。

### Non-Goals

- 不保证 LLM 校订或摘要绝对正确，不用模型自报置信度替代引用校验。
- 不实现远端 ASR、双模型识别、本地 LLM、说话人分离、翻译、协作或云同步。
- 首版不自动补转写；唯一例外是用户对已有文字段或 GAP 段显式发起、使用会话固定本地模型的“重新识别”，不引入第二模型或远端 ASR。
- 不为“永不被系统杀死”设计规避机制，不提供隐蔽录音。
- 不把未经基准验证的模型速度、准确率、工件溯源或设备码率支持写成既成事实。

## Decisions

### 决策 1：Flutter 负责体验，Android 原生负责持续音频与本地 ASR

建议模块：

| 模块 | 技术 | 职责 |
|---|---|---|
| `app_shell` | Flutter | 三页导航、依赖组装、设置与生命周期展示 |
| `capture_android` | Kotlin | 麦克风前台服务、AudioRecord、PCM 分发、块占位与 AAC 封存 |
| `asr_android` | Kotlin + sherpa-onnx | X-ASR 流式推理、端点、跳读、手动重识别、时间戳 |
| `core_data` | drift/SQLite + 文件存储 | 事务、迁移、版本、任务、租约与导出索引 |
| `intelligence` | Dart | 预处理、BYOK、折叠编排、标题与多源引用校验 |
| `reader` | Flutter | `ReaderContext`、振幅、实时时间轴、折叠、手势、滚动与动画 |
| `playback_export` | Media3/just_audio + Kotlin export bridge | 跨块回听、音频合并导出 |

PCM 不经过高频 Dart MethodChannel 拷贝；原生采集后直接分发给原生 ASR 和编码器。Flutter 只接收振幅采样、识别事件和状态。BYOK 与语义编排可在 Dart 中运行，不拥有麦克风生命周期。

**备选**：纯 Flutter 插件组合初期更快，但 PCM 分流、长时前台服务、原子块占位、独立分块封装和恢复难以统一验证，因此只把插件用于边界清晰的 UI、网络、存储和播放能力。

### 决策 2：显式会话、单路 PCM 与有界分发

- 用户从可见界面点击大红按钮开始；系统支持的合规通知入口只提供暂停/继续和打开应用，不在任意后台状态新启动麦克风。
- 服务启动后立即进入麦克风类型前台状态，再获取音频资源；失败显示明确原因。
- AudioRecord 以设备支持的采样率采集单声道 PCM 16-bit，优先 48kHz；同一路数据分成：
  1. 重采样至 16kHz 的 ASR 流；
  2. 目标 192kbps AAC-LC 编码流；
  3. 低频振幅 RMS/峰值采样流。
- 采集线程只读取、标记单调递增采集序号和时间，并写入有界采集队列；ASR、AAC 编码和持久化队列分别有界。振幅只保留采样，不允许其反向阻塞音频。
- 所有队列有容量、 oldest/newest 采集序号和积压时长指标。音频不得静默丢弃；ASR 跳读只是不再把明确区间送给本轮识别，原 PCM/AAC 证据仍须保存。
- AAC 队列或持久化不能消费时，系统先施加背压；不能在不丢音频的前提下继续时，进入明确停止/失败流程，不扩容为无限内存，也不以“正在录音”掩盖未保存内容。
- LLM 任务可以合并、推迟或淘汰后重建；音频采集、AAC 与持久化不得套用这种可丢弃策略。
- 暂停停止采集并封存当前块；继续在同一会话创建新块，墙钟时间保留暂停间隙，实际音频 offset 不包含该间隙。
- 不使用 WorkManager 执行持续录音；它只负责延迟生成、清理与导出等可延迟任务。

#### 三个时间域不得混用

| 时间域 | 字段与用途 | 约束 |
|---|---|---|
| UTC 墙钟 | `createdAtUtc/sealedAtUtc/finalizedAt/foldDueAt/revealedAt` | 持久化、跨重启排序和展示；不得直接用于 PCM 寻址或 15 秒排队判定 |
| 采集单调时钟 | `captureStartedMonoNs/captureEndedMonoNs`、ASR 队列时延、波形推进 | 必须记录时钟域标识；同一设备会话内比较，不将其他设备或重启后的裸数值当作同轴时间 |
| 实际采集 offset | `capturedStartMs/capturedEndMs`、文字/GAP 区间、回听与导出定位 | 从会话实际采集内容起算，排除暂停间隙；ASR 跳读区间仍属于已采集音频，不从 offset 中删除 |

会话保存 UTC 与单调时钟的映射锚点及映射质量信息；重启后建立新锚点，旧单调值只与原锚点共同解释。UI 日期本地化不改变持久化值。运行时折叠调度可将 UTC 到期时间映射为单调剩余时长，但持久化判定仍以 `foldDueAt` 为准。

### 决策 3：60 秒初始 AAC/M4A 分块与先占位后切换

- 首版以 60 秒作为待验证的初始分块配置，每块目标为可独立播放的 M4A；暂停、结束、低存储停止和异常恢复也处理当前块。最终默认配置须依据 30/60/300 秒对照结果冻结，不把 60 秒写成实测最优值。
- 目标编码为 AAC-LC、单声道、192000 bit/s；实际采样率、码率和编码器能力写入 `AudioChunk`。
- 192kbps 理论数据量约为 86.4MB/小时、1.44MB/分钟，不含容器开销；仅用于容量估算，不是设备实测结果。
- MediaRecorder 允许平台裁剪不支持的码率，因此实现以 AudioRecord + MediaCodec/MediaMuxer 为主，并在设备能力不满足时显式报告实际值，不静默宣称达到 192kbps。
- 导出按 `chunkSeq` 连接实际录音，不插入暂停静音。优先使用 Media3 Transformer 转封装；不兼容时才重编码并明确产物参数。
- 合并写入临时文件，校验时长与可解码性后原子改名；源块不变，导出失败可重试。

#### 新块原子占位顺序

自动分块、暂停后继续或任何需要新编码资源的切换，必须复用同一协议：

1. 将会话分发状态切为 `BLOCKED`，确定旧块切点的采集序号、单调时间和 `capturedEndMs`，立即停止向 ASR/AAC 分发切点后的新 PCM。
2. 切点后的 AudioRecord 数据只能暂留在既有有界采集队列，不得另开无限缓冲或静默覆盖。旧块切点前已经分发的 PCM 按序排空并进入 `SEALING`；ASR 可继续处理切点前已排队数据，但不得越过切点。
3. 在会话内预留下一序号，以 `(sessionId, chunkSeq)` 唯一约束、唯一临时路径、`PLACEHOLDER` 状态和 `createdAtUtc` 原子持久化新块，并在同一事务中推进活动块指针。数据库提交及所需目录持久化完成前不得初始化编码器。
4. 占位成功后初始化并验证新编码器、muxer 与输出资源；首帧实际分发时记录 `captureStartedMonoNs/capturedStartMs`，将块置为 `OPEN`，然后解除 `BLOCKED`，按采集序号继续向 ASR/AAC 分发。
5. 旧块独立完成校验、原子改名和 `SEALED` 提交。旧块封存与新块占位通过同一事务日志关联，崩溃恢复不得重复分配序号或把两个块同时视为可写活动块。

占位持久化失败时，不得初始化新编码器、不得解除 `BLOCKED`、不得继续伪装录音。系统保护旧块和已排队证据，停止后续采集并展示可诊断失败；未保存部分必须标为失败区间，不能计为正常暂停或零丢失。编码器初始化失败同样不接收新 PCM，按资源失效路径停止或仅在旧块证据完整且资源世代明确隔离时重试整个占位协议。

正常自动分块必须提前预留“当前块正常封存 + 下一块占位/初始化 + 数据库日志”的空间和队列余量。余量不足时在普通块边界前进入低存储停止顺序，不能先写满再处理。

#### 块状态与恢复语义

| 状态 | 含义与允许动作 | 禁止动作 |
|---|---|---|
| `PLACEHOLDER` | 身份、临时路径和序号已持久化，尚无可分发 PCM 的已验证编码资源 | 不得当作可播放块，不得跳过占位直接写正式文件 |
| `OPEN` | 编码资源有效，接受同一块切点内的 PCM | 不得并行接受下一块写入 |
| `SEALING` | 已切断新分发，正在排空、结束容器、同步和校验 | 不得重新打开追加，不得提前展示为完整封存 |
| `SEALED` | 时长、校验、可解码索引和最终路径提交完成 | 不得原地覆盖；用户删除除外 |
| `SEAL_FAILED` | 封存未完整提交，记录失败阶段和资源世代 | 不得无条件继续录音，不得把残留文件当成完整块 |
| `RECOVERABLE` | 恢复后仅部分可证明一致，可索引可解码部分并量化边界 | 不得伪装成正常 `SEALED`，不得忽略尾部损失 |
| `CORRUPT` | 无法证明可解码或时间映射不可信 | 不得用于默认回听、导出成功或重识别输入 |

`SEALING` 不是可续录状态：分发保持 `BLOCKED`，直到旧块完成且新块 `OPEN`。`SEAL_FAILED` 后只有在切点前 PCM 均已入账、残留 writer 已关闭、旧块转为可恢复终态、下一资源世代未失效时，才允许重新执行完整的“占位 → 初始化 → 分发”协议安全续录。存储耗尽、编码器/muxer 资源失效、时间映射断裂或损失无法量化时必须停止采集并等待显式处理，不能借续录掩盖故障。

正常封存采用“临时写入 → flush/同步 → 校验 → 同卷原子改名 → 数据库提交 `SEALED`”的可恢复顺序。恢复扫描根据稳定块 ID、路径、校验和及事务日志判断：完整产物可补交 `SEALED`；仅有可解码前缀则转 `RECOVERABLE` 并记录实际边界；无法验证则转 `CORRUPT`。任何恢复都不得覆盖历史版本或复用已分配序号。

### 决策 4：顶部振幅与录音按钮手势

- 顶条最新样本从右侧进入，历史样本向左移动；采样与绘制使用单调时钟，不因 UI 帧率改变音频时间。
- 录音时按钮为大红色录音态，开始后变为暂停态，暂停后可继续；暂停时波形冻结并降低强调，新会话显示空波形。
- 只有录音或暂停状态允许左滑结束。空闲状态左滑不创建空会话。
- 按钮拖动手势使用实际累计水平位移；96dp 与“轨道不足时使用可用宽度 40%”仅为交互原型候选初值，须在评审前冻结，不作为已验证可用性结论。
- 释放时只有实际左向位移超过冻结后的阈值才成功。速度/甩动只影响接续动画，不能补偿不足位移。
- 达标后先按块协议封存当前音频和文字，再创建空闲新会话并停留在中间录音页；不自动开始录音。
- 未达标、取消或封存失败时，从当前位置和速度弹簧回到原状态，旧会话继续有效；失败期间不得继续分发无法持久化的新 PCM。
- 手势与波形区域隔离，波形本身不消费水平拖动。

### 决策 5：外置 X-ASR 480ms 单模型、工件溯源与租约

统一输出：

- `Partial`：可覆盖临时文字、当前时间范围和模型版本。
- `FinalCandidate`：稳定前缀、端点和可用时间戳。
- `Final`：提交的不可变 ASR 版本，包含 UTC `finalizedAt`、采集单调时间和实际采集 offset。
- `Health`：实时系数、 oldest 未处理 PCM 的单调排队时延、线程、内存、队列容量和错误类别。

首版原型采用 X-ASR 480ms INT8，目标是中文和中英混合；SenseVoice 只作离线基准对照，不进入运行时双模型管线。480ms 是模型块长，不等于端到端首字延迟。模型是否继续采用由冻结基线上的语义正确性门槛和速度结果共同决定。

必须实际试验高于当前基线一档的候选，型号尚未确定。先按中文/中英混合能力、Android CPU 兼容性、来源与许可筛选候选，再冻结其精确工件、上游 revision、SHA-256、转换链和配置；保留任务 1.3 原固定 X-ASR 四工件作为基线，在同一预注册 manifest、评分器、计时方法及双参考设备上对比准确率、RTF、首字/落后、内存、热稳定与功耗，并依据完整实测决定保留或替换。不得仅列为可选，不得预言高一档效果更好，不得降低准确率门槛、持续 `RTF < 1` 或 p95 落后预算；离线候选比较不构成运行时双模型。

模型独立于 APK：

- 清单包含模型 ID、版本、签名清单代数、渠道、运行时最低版本、ABI、URL/镜像、压缩与解压大小、SHA-256、许可和能力标记。
- 远程清单必须使用 HTTPS，并由应用内置受信公钥验证 detached signature（例如 Ed25519）；公钥轮换须由旧公钥签发过渡声明。已验证渠道拒绝代数低于本机已接受值的清单，防止回滚到旧模型；用户手动导入单独标为 `MANUAL`，由用户显式确认本地文件，不冒充受信远程来源。
- 每项工件还须记录上游作者/发布方、上游仓库与模型卡、不可变上游 revision、原始文件名、上游声明哈希（若有）、本地计算哈希、获取时间、量化/转换工具及版本、转换配置与脚本哈希。上游声明、本地验证和项目实测分栏记录，缺失项明确为未验证，不能补造来源、哈希、大小、许可或能力结论。
- 支持应用内下载、手动导入、断点续传、校验、原子安装、删除和回滚。安装只接受完整清单与全部工件校验通过的世代。
- 正在进行的会话固定 `modelId/modelVersion/installationId/asrConfig`，实时识别、该会话所有文字段/GAP 段重识别都使用这一固定版本；更新只影响新会话。
- 无可用或尚未就绪模型时，顶部唯一录音控制不得假启动实时转写；等待、进入设置处理或显式确认仅录音的错误/确认反馈放在中间结果区外。首版不在模型恢复后自动补转写既有音频，用户只能逐段手动重识别。

#### 启动预加载、权重复用与设置入口

- 应用打开立即异步预加载已选模型，初始化不等待开始录音且不阻塞界面。设置提供模型导入、刷新、选择、安装/重试、更新、回滚与删除等真实可执行操作，并可查缺失、准备中、就绪、失败与必要错误。
- 按模型工件、安装版本及运行配置复用进程内已加载权重；开始、新会话、暂停和继续不卸载权重。会话与重识别分别持有隔离的 stream/解码上下文、缓存、端点、时间映射和事件世代；暂停冲刷可提交结果，继续沿同会话时间轴恢复，换会话清理旧流，旧事件不能污染新流。
- 显式切换模型/配置、资源回收、运行时失效和进程重启可触发重建；设置记录重建原因、实例世代及准备/失败状态，不承诺永不重载。重建不得绕过活动会话固定模型、租约与失败保护规则。
- 中间区域始终只展示 ASR 结果，空闲或仅录音且没有结果时留空，不放能力说明、模式、状态、模型管理或第二开始按钮。模型管理全部进入设置，必要错误/确认在结果区外。
- 设置只保留真实可操作、可调整项目与其必要值/状态/错误；不陈列需求说明、外观动效介绍、当前模式或不可操作占位。

#### 模型租约与 `pending-delete`

- 活动录音会话在加载模型前获得持久化 `ModelLease`；每次手动重识别也必须在读取模型前获得对应固定版本的租约，并在完成、失败或取消后释放。
- 删除仍有有效租约的安装时，只把安装原子标记为 `pending-delete`，保留全部工件，不允许新租约；既有租约可完成其既定工作。最后一个租约释放后才能删除文件并移除安装索引。
- 进程重启先恢复租约与活动会话/重识别任务，不能仅按进程内引用计数删除文件。已崩溃任务的租约经恢复事务确认无人使用后释放，再继续 `pending-delete` 清理。
- 回滚与更新不得删除其他世代仍持有的文件。历史会话不永久占用租约；其后的手动重识别需重新取得原固定版本租约，若该版本不可用则明确失败，不得改用新版、第二模型或远端服务。

### 决策 6：15 秒显式跳读、Final 预处理与独立折叠

语音段状态：

```text
ACTIVE → FINALIZING → FINAL → PROCESSING / READY / FAILED
                     └────────→ FOLD_DUE（独立计时）

ASR_OVERLOAD → 持久化 GAP L0 → 跳至最新音频继续识别
GAP ──用户手动重新识别──> 新不可变 ASR 版本（成功有效才改变默认展示）
```

#### ASR 超过 15 秒的跳读协议

- 以采集单调时钟计算 `newestCapturedMonoNs - oldestUnprocessedPcmMonoNs`。 oldest 未处理 PCM 包括已入队与正在推理但尚未形成可提交结果的输入；不使用墙钟、UI 帧时间或模型自报延迟。
- 当该排队时延**超过 15000ms**时，立即触发一次跳读，而不是继续无限积压。15 秒是已确认的行为阈值，不是实测首字延迟目标。
- 系统冻结跳读边界：起点为本轮最早未处理音频的实际采集 offset，终点为跳读时已由音频持久化路径接收的最新安全采集序号对应 offset。先把可确定的 FINAL 按原顺序提交，再持久化一个显式、不可变 GAP L0；Partial 不得充当已保存证据。
- GAP 的 `reason=ASR_OVERLOAD`，记录跳过音频的 `capturedStartMs/capturedEndMs`、对应单调时间和模型版本。文字流在按时间排序的位置插入一行居中的字面量 `...`，不得插入空白、伪文字或将缺口并入相邻 FINAL。
- 随后使跳读世代之前的 ASR 事件失效，清空的是本轮 ASR 待识别输入而不是音频证据，并从跳读终点后的最新 PCM 继续识别。迟到的旧世代结果不得写进 GAP 或其他段。AAC 采集与封存继续，跳读区间仍可回听和手动重识别。
- 每次实际跳读产生一个有稳定 ID 的 GAP；健康采样重复报告同一次过载不得重复插入。再次发生独立跳读时另留证据，不能原地延长旧 GAP。
- GAP 不获得自动 L1/L2/L3 或自动折叠资格，也不以 `...` 参与语义生成。手动重识别成功产生有效文字 FINAL 后，才按该新源版本获得预处理和折叠资格。
- 过载恢复只恢复后续实时识别，不自动重识别 GAP，不在后台批量补转写。

#### 普通 FINAL 与折叠

- 端点由 VAD、ASR 端点、标点和长度共同决定，避免机械截词。段落长度上下限属于预注册数值预算，须在模型决策前冻结，不使用未经验证的固定秒数冒充最佳分段。
- `FINAL` 是不可变证据，UTC `finalizedAt` 是该段自动折叠计时依据。
- 一个或相邻多个 FINAL 文字足够形成完整段落时立即生成 L1/L2；不等待折叠延迟，不要求额外稳定期。
- 太短的分片可与下一 FINAL 合并为语义段，但每个源段时间戳仍独立保留。`TranscriptSegment.sourceFinalIds[]` 按阅读/音频顺序保存且不得无序去重；同一 FINAL 不得重复出现。
- 普通文字段 `foldDueAt = max(sourceFinal.finalizedAt) + 当前配置延迟`。GAP 的 `sourceFinalIds[]` 为空且 `foldDueAt` 为空；成功重识别后以新有效 FINAL 集重新建立该段计时。
- 折叠配置变化时，只重算配置生效时尚未到期的段；已到期段保留原到期事实，不重置、不补等一个周期。配置变化不影响预处理资格。
- 到期且 L2 就绪则自动收起；到期但未就绪则继续显示 L1/FINAL，L2 成功后立即折叠，不再等待一个周期。
- 无网络、BYOK 未配置或生成失败时保留 FINAL/L1，并显示未整理状态，不展示空白摘要。
- 停止或暂停会冲刷可处理 FINAL；“立即整理”可主动重试失败任务，但不改写证据，也不触发自动 GAP 补转写。

### 决策 7：三级阅读 + L0，证据与生成物版本化

| 层 | 粒度 | 生成方式 | 失败回退 |
|---|---|---|---|
| L0 证据 | FINAL、GAP 及其不可变版本 | 原始 ASR、显式跳读、用户手动同模型重识别、差异与音频定位 | 不适用 |
| L1 校订全文 | 稳定语义段 | 保守纠错、标点、口头重复清理 | FINAL；GAP 保持 `...` |
| L2 段落要点 | 语义段/小节 | 生成短要点，绑定有序源版本和引用 | L1/FINAL |
| L3 会话摘要 | 话题/会话 | 聚合 L2，形成主题卡片和摘要 | L2 |

- 阅读流中每个普通文字段在 L1/L2 间展开收起；L3 是聚合摘要卡，可展开到关联 L2，再展开到 L1。GAP 只展示 `...`、缺口原因及可用证据，不生成空白要点。
- 单击折叠文字逐级展开；双击将当前节点收回其最短档。
- 用户手动展开的段在当前 `ReaderContext` 中固定，不再次自动折叠；只有双击解除并收起。
- 自由阅读不豁免其他到期段，位置通过锚点保持。
- 低层尽量保守，高层才生成新表述。L2/L3 每个独立事实性陈述至少绑定一个来源范围；标题可引用整个节点。
- 所有产物保存有序 `sourceVersions[]` 与规范化 `sourceSetHash`，不能只保存“最新源哈希”而丢失多源顺序和逐项身份。

### 决策 8：BYOK 多源校验、HTTPS 与安全重定向

- 用户配置 Base URL、API Key 和模型名；Android 直接请求 `/v1/chat/completions` 兼容端点，无中继。
- BYOK Base URL 首版 SHALL 使用 HTTPS；不得把明文 HTTP 作为静默回退。模型下载同样默认 HTTPS，校验哈希不能替代传输来源展示。
- 首次启用显示将离机的数据类型和目标源（scheme、host、port）；音频永不包含在 LLM 请求中。
- 同源重定向可按冻结的次数预算处理，HTTPS 降级到 HTTP 必须拒绝。跨源重定向（scheme、host 或有效 port 任一变化）MUST NOT 转发 `Authorization`、Cookie 或其他凭据，也不得自动重放含用户文字的请求正文；系统把它视为未经确认的新目标，要求用户重新确认/配置后才能发送。
- 优先使用端点支持的 JSON Schema/structured output；不支持时使用严格 JSON + 客户端解析修复重试，不依赖 Markdown 围栏。
- 请求包含任务类型、节点 ID、有序 `sourceVersions[]`、规范化 `sourceSetHash`、允许操作、来源文本和引用范围；响应必须逐项回显同一有序列表及哈希，并包含操作/产物、引用和模型元数据。
- `sourceVersions[]` 每项至少含稳定的 `sourceId/versionId/sourceKind`，顺序与语义输入顺序一致。`sourceSetHash` 使用带模式版本的规范 JSON（对象键固定、UTF-8、无无意义空白、数组顺序保留）计算 SHA-256；不得排序数组、只哈希末项或使用可读拼接字符串代替。
- 客户端在响应接收、缓存读取/命中和事务提交三个边界都逐项比较 `sourceId/versionId/sourceKind` 及 `sourceSetHash`。任一项缺失、换序或失效，整个结果不得成为默认有效版本，不允许部分提交。
- 提交时在单个数据库事务内重新读取每个当前有效源版本；全部一致才写入产物及依赖。迟到结果进入非默认历史或按策略丢弃，不覆盖新版本。
- L1 使用替换/保留操作，禁止无依据增加数字、人名、结论或行动项。引用必须落在提供来源范围内，提交前验证；校验失败则重试有限次数，最终回退低层。
- 缓存键和幂等键包含任务类型、提示词版本、完整 `sourceSetHash`、有序源列表、模型名和参数。重复 job key 幂等，不重复追加；哈希碰撞防御仍依赖逐项比较。

### 决策 9：手动编辑与逐段同模型重识别

- 每个文字段，包括显示 `...` 的 GAP，长按菜单都必须提供“重新识别”；普通段还可编辑文字、播放对应录音、复制。GAP 的 L0 不可编辑，复制只得复制实际可见的 `...`。
- 重识别使用该段所属 `RecordingSession` 固定的本地模型、会话 `asrConfig` 和原始音频区间，可在完全离线时执行。请求不得把音频送往 BYOK/远端 ASR，不得选择另一模型来提高成绩。
- 输入只来自请求时冻结的不可变音频区间和可验证块。所需块仍为 `OPEN/SEALING` 时等待其成为可验证输入；`SEALED` 或具有可信映射的 `RECOVERABLE` 块可按其可解码范围使用。区间包含 `CORRUPT` 或无法解码部分时，不得声称完整重识别成功。
- 同一段同一时刻只允许一个活动重识别任务，重复点击通过稳定任务 ID 幂等；活动会话历史不会自动批量触发该任务。
- 重识别产生新的不可变 L0 ASR/FINAL 版本，保留其父版本、固定模型元数据、输入音频区间和新的 `finalizedAt`。原始 GAP、原始文字及已有版本永不覆盖。
- 只有推理完整结束且音频映射、模型身份、结果结构和提交事务均验证成功的新版本，才成为默认展示并驱动下游过期重建。原始 GAP 仍可在版本历史中查看，默认展示不再显示 `...` 仅在成功生效后成立。
- 失败、取消、模型缺失/损坏、租约无法取得或输入不可验证时保留重识别前的默认展示；若原是 GAP 就继续显示居中的 `...`，并显示可重试的脱敏原因。
- 对普通文字段成功重识别同样新增 L0 版本，不直接改写 L1 用户版本。已有用户校订保留在历史/可用版本中，系统须明确展示重识别 L0 与用户 L1 的层级关系，不得借重识别覆盖用户文字；下游 AI 产物按新有效来源重建。
- 编辑修改 L1 用户版本，不修改 L0。编辑界面可对照原始 ASR、重识别版本与当前校订。
- 保存用户编辑后关联 L2/L3 和自动标题标为过期；后台重新生成，但不得覆盖用户文字。
- 用户版本优先于后续 AI 校订。删除用户版本才可回到已有 AI 版本或当前有效 L0 FINAL。
- 正在录音时长按回听只提示“请先暂停录音”，不自动暂停；暂停或空闲时才允许播放。手动重识别不是回听，不得暗中改变录音状态；其音频读取不能抢占采集与封存资源。
- 回听依据引用跨块建立播放序列并定位到 `capturedStartMs/capturedEndMs`，不把暂停间隙计入寻址。

### 决策 10：跟随底部与自由阅读互斥

状态：

- **跟随底部**：默认状态，或用户手动划到底部后进入；新内容到来保持底边可见。
- **自由阅读**：手指在滚动区按下或发生用户滚动立即进入；显示“回到最新”按钮，新内容不抢滚动位置。

程序滚动事件不能误判为用户滚动。回到最新使用可打断弹簧/缓动，抵达底部后恢复跟随。

| 当前模式 | 展开 | 折叠 | 锚点 |
|---|---|---|---|
| 跟随底部 | 向上展开 | 由上至下收起 | 底边，避免把最新内容提走 |
| 自由阅读 | 向下展开 | 由下至上收起 | 顶边/当前阅读项，避免位置跳动 |

几何变化通过布局前锚点、预测量与补偿实现，不能在动画结束后才跳变修正。用户新手势从当前位置与速度接管。

### 决策 11：统一弹簧动效，但不让所有属性回弹

采用 Flutter `AnimationController`、`SpringDescription`、`SpringSimulation` 和内建滚动组件。弹簧满足：

\[
m\ddot{x}+c\dot{x}+k(x-x_t)=0,\qquad \zeta=\frac{c}{2\sqrt{km}}
\]

欠阻尼时：

\[
x(t)-x_t=e^{-\zeta\omega_nt}\left[y_0\cos(\omega_dt)+
\frac{v_0+\zeta\omega_ny_0}{\omega_d}\sin(\omega_dt)\right]
\]

其中 \(\omega_n=\sqrt{k/m}\)，\(\omega_d=\omega_n\sqrt{1-\zeta^2}\)。

- 几何和按钮拖动使用接近临界阻尼的弹簧；透明度用短缓动，避免文字持续晃动。
- 新操作继承当前位置和速度，可中途反向，不从头播放。
- 展开、折叠、点击、长按、弹窗、回底按钮、标题替换和录音状态转换使用统一动效 token。
- 标题从占位文本交叉淡化并轻微位移到新标题，不在生成后提前覆盖，不循环播放。
- 系统“移除动画/减少动态效果”开启时取消弹簧和位移，只保留即时状态与必要淡入淡出。

### 决策 12：三页导航、ReaderContext 与标题首次可见事务

- 底部顺序固定为录音列表、录音、设置；使用 `IndexedStack` 或等效状态保留机制。
- 页面切换不暂停录音、ASR、下载、手动重识别或处理队列。
- `ReaderContext` 以 `sessionId` 为键、仅在内存保存当前阅读会话的滚动模式、阅读锚点、程序滚动标记和手动展开段 ID 集。
- 在录音列表、录音、设置三页间切换，或同一会话界面重建，不结束当前 `ReaderContext`；手动展开锁与自由阅读位置继续有效。
- 进入另一 `sessionId` 时清除旧会话上下文并为新会话建立默认跟随底部上下文；进程重启清除全部内存上下文。已持久化的文字、版本、`foldDueAt` 和标题状态不受影响，重启后已到期且未锁定的段可按既有到期事实处理。
- 新录音以日期时间作为占位标题；获得足量稳定文字后生成标题。
- `TitlePresentation` 持久化 `generatedVersion/pendingFirstReveal/revealedAt/sourceVersions[]/sourceSetHash`。
- 当 `revealedAt` 为空时，最新校验通过的标题版本继承现有 `pendingFirstReveal`，旧标题版本不竞争消费资格；若动画进行中，展示目标切换到最新有效版本，完成后只提交实际展示版本及 `revealedAt`。
- 若生成时条目实际可见，立即动画替换；否则保持占位，待第一次可见再播放。动画完成后才标记已展示；若中途离开，继续保留待展示状态。
- 一旦 `revealedAt` 已提交，后续有效标题只进行普通轻量更新，不重新设置 `pendingFirstReveal`，也不因重启或列表重建重播首次动画。
- 标题生成、响应回显、缓存和提交同样逐项检查有序 `sourceVersions[]`；旧来源标题不能覆盖新来源标题。

### 决策 13：长期保留与低存储停止顺序

- 音频和文字默认保留至用户明确删除；不自动删除最早内容。
- 预警阈值综合考虑预计录音增长、当前块封存、下一块占位、导出临时空间和数据库日志。具体阈值属于预注册数值预算，不以理论码率代替实测容器与文件系统开销。
- 达到预警时显示剩余可录时长及估算条件；系统在正常分块前预留封存和占位空间。
- 达到硬下限后必须严格按以下顺序停止：
  1. 会话进入低存储停止态并将分发放置为 `BLOCKED`，记录最后接收的采集序号/单调时间/实际 offset，立即停止向 ASR/AAC 分发该切点后的新 PCM，不创建下一块占位。
  2. 只排空切点前已经分发的有界队列，当前块从 `OPEN` 转为 `SEALING`；结束 AAC/muxer、同步文件并计算校验。存储不足不能靠继续写入其他卷来伪装同一块成功。
  3. 完成当前块 `SEALED` 提交，随后冲刷已确定 FINAL、GAP、任务与数据库元数据。来不及形成的 ASR 结果按 15 秒跳读规则留下 GAP，不能为等待 ASR 而无限推迟音频封存。
  4. 只有音频封存与数据库冲刷都成功，才把会话标为低存储暂停并释放麦克风/编码资源。UI 显示实际停止边界，不把失败显示成用户正常暂停。
- 任一封存或冲刷步骤失败时保持 `BLOCKED`，将块置为 `SEAL_FAILED` 或可证明的恢复状态并显示保存异常；不得继续采集，不得创建新会话掩盖失败。
- 空间恢复后由用户显式继续；继续时从完整的新块占位协议开始，不自动无感重启。
- 导出前检查源块、临时文件和目标卷空间，失败不删除源块或除可安全清理半成品之外的临时文件。

| `AudioChunk` | `id/sessionId/chunkSeq/tempPath/finalPath/createdAtUtc/sealedAtUtc/captureStartedMonoNs/captureEndedMonoNs/capturedStartMs/capturedEndMs/codec/sampleRate/bitRate/duration/checksum/state/resourceEpoch`；`(sessionId,chunkSeq)` 与路径唯一，`state=PLACEHOLDER/OPEN/SEALING/SEALED/SEAL_FAILED/RECOVERABLE/CORRUPT` |
| `TranscriptSegment` | `id/sessionId/kind=TEXT/GAP/ordered sourceFinalIds[]/finalizedAt/foldDueAt/captureStartedMonoNs/captureEndedMonoNs/capturedStartMs/capturedEndMs/status/reason`；GAP 的 `reason=ASR_OVERLOAD`，默认字面展示 `...`，跳过区间不可变 |
| `TranscriptVersion` | `id/segmentId/kind=ASR/GAP/AI/USER/text/parentVersionId/modelId/modelVersion/finalizedAt/createdAtUtc`；不可变，成功重识别新增 ASR/FINAL 版本而不覆盖旧版本 |
| `SemanticNode` | `id/sessionId/parentId/kind/orderKey/sourceRange` |
| `SemanticArtifact` | `id/nodeId/level/version/content/citations/sourceVersions[]/sourceSetHash/status/modelMeta`；源数组有序且逐项可追踪 |
| `ProcessingJob` | `idempotencyKey/type/sourceVersions[]/sourceSetHash/state/attempts/notBefore/error`；响应、缓存与提交共用同一源身份 |
| `ModelInstallation` | `installationId/modelId/version/path/manifestHash/manifestGeneration/channel/signatureVerified/artifactProvenance/installState/verifiedAt/pendingDeleteAt`；`pending-delete` 时工件仍受租约保护，已验证渠道拒绝代数回退 |
| `ModelLease` | `leaseId/installationId/modelId/modelVersion/ownerType/ownerId/acquiredAtUtc/releasedAtUtc/recoveryState`；有效租约阻止物理删除 |
| `TitlePresentation` | `sessionId/generatedVersion/pendingFirstReveal/revealedAt/sourceVersions[]/sourceSetHash`；未 revealed 的最新有效版本继承首次展示资格 |
| `PlaybackAnchor` | `sessionId/segmentId/audioChunkIds[]/capturedStartMs/capturedEndMs`；只使用实际采集 offset 寻址 |

`ReaderContext` 不是持久化实体：按会话保存于内存，三页切换保留，换会话或进程重启清除。

所有业务墙钟使用 UTC 持久化，音频内部位置使用带时钟域标识的单调时间与实际采集 offset；UI 日期再本地化。`sourceFinalIds[]`、`sourceVersions[]` 和 `audioChunkIds[]` 的数组顺序具有语义，不得当成无序集合存储。

文件与数据库使用“占位身份原子提交 → 临时写入 → 校验/同步 → 原子改名 → 状态提交”的可恢复协议。语义产物采用“逐项源校验 → 单事务写入版本与依赖”的协议，两类协议不得用未经检查的晚到结果互相覆盖。

## Processing and Reliability

优先级从高到低：音频采集、块占位/AAC/封存与持久化、ASR、实时 UI、用户显式编辑/回听/重识别、标题、L1/L2、L3、非必要导出维护。用户重识别可以离线运行，但不得令音频队列无限增长或挤占当前块封存。

所有采集、AAC、持久化、ASR 与 LLM 队列必须有界；资源紧张时暂停生成而不是积压无限任务。音频正常路径零丢失，ASR 跳读必须留下 GAP，AAC 无法继续则必须停止并报告，二者不能混为“自动丢音频保实时”。

- 网络错误指数退避并尊重用户取消；端点鉴权错误不盲目重试。退避、重试和重定向次数为预注册预算。
- BYOK 只传当前任务必需的稳定文字与有限上下文，设置预注册最大字符/token 预算。
- 服务重启后扫描 `PLACEHOLDER/OPEN/SEALING/SEAL_FAILED`、未提交任务、模型租约和源版本哈希；音频可修复则恢复索引，不可修复则明确标记。
- 恢复以资源世代隔离旧 writer、ASR 事件和重识别事件。已失效世代不能继续提交；涉及音频的任何舍弃都必须对应可量化区间，正常路径不得发生。
- 任务完成提交必须逐项检查有序源版本；过期结果进入历史或丢弃，不覆盖新版本。
- 日志不含 API Key、`Authorization`、完整录音文字或请求正文；诊断导出默认脱敏，但可包含队列时延、GAP 区间、块状态和量化损失。

## Validation Strategy

### 验收顺序与阶段出口

1. **文档同步出口（已完成结构校验）**：能力规格、任务、评测与评审清单已同步，并消除旧的“是否支持补转写待定”、单一 `sourceHash`、无占位切换等规则。OpenSpec 严格校验只证明结构有效，不等于可实施或行为通过。
2. **预注册冻结出口**：在模型继续/替换/调参决策之前，冻结两台参考设备、可复现数据集及版本、文本规范化、语义正确性门槛、速度与资源预算、队列容量、故障矩阵和统计方法。冻结记录须含哈希与配置，不能在看到结果后移动门槛。
3. **30 分钟可行性尖刺**：在两台参考设备分别执行，验证 Flutter/Kotlin 通道、前台录音、单路 PCM、有界队列、外置模型加载与时间戳、AAC 占位/封存和 Media3 合并。它只回答技术可行性，不替代发布长测。
4. **分块与模型决策**：比较 30/60/300 秒的异常尾部损失、文件数量、封装/存储开销、恢复时间和回听索引，再冻结分块默认值。模型先满足冻结的语义正确性基线，再在合格方案中优先更快且热稳定的配置；不得为速度降低正确性门槛，也不得用离线对照模型形成运行时双模型。
5. **实现与行为验收**：按同步后的规格实现，执行单元、契约、交互、故障注入和安全测试。两台设备分别报告，不混排为同一成绩。
6. **两小时发布长测**：与 30 分钟尖刺分开重新执行，覆盖持续采集、自动分块、ASR 跳读、BYOK 断续、页面切换、折叠和恢复；不能用尖刺结果豁免。
7. **发布出口**：正常录制零音频丢失、证据不可变、引用与多源版本有效、秘密不泄露均为阻塞条件。只有故障矩阵明确列出的崩溃/资源故障可评估尾部损失，且必须量化并对照预注册上限；未列出、不可量化或超上限即失败。

### 预注册项而非虚构实测值

| 项目 | 当前设计值 | 冻结/报告要求 |
|---|---|---|
| ASR 跳读阈值 | 排队时延超过 15000ms | 用户已确认；使用单调时钟，测试等于阈值不触发、超过阈值触发 |
| 分块候选 | 30/60/300 秒；60 秒为初始默认 | 先对照再冻结；不得宣称某档实测最优 |
| AAC | AAC-LC、单声道、目标 192000bit/s | 记录实际参数、容器开销和设备偏差 |
| 分段、手势与动效参数 | 原型候选 | 在交互/模型决策前冻结，报告依据，不把候选值称为最佳 |
| Partial/Final 延迟、RTF、内存、温度、功耗、慢帧 | 数值待冻结 | 预注册 p50/p95 等统计口径和上限，实测后分别报告 |
| 队列容量、存储预警/硬下限、重试/重定向/token 预算 | 数值待冻结 | 在对应实现验收前冻结，禁止无限队列和结果后调整 |
| 正常录制损失 | 0 | 以采集序号、时间和解码样本对账 |
| 指定异常尾部损失 | 按故障场景待冻结 | 逐场景量化并设上限，不设“崩溃均可损失”通用豁免 |

参考设备至少为一台中端和一台较低配置 ARM64 Android 设备；具体型号、SoC、RAM、OS/补丁、厂商电池策略、可用存储、温度区间及模型运行线程须在测试前登记。数据集冻结内容至少包括音频清单与 SHA-256、来源/许可、采样参数、人工参考转写、中文/中英/噪声/口音/静音类别、长会话材料、文本规范化规则、语义事实与引用答案、数据划分和随机种子。模型作者数据、公开样例和本项目实测不得混为同一基线。

### 新协议的可测试场景

以下场景是同步 specs/tasks 与验收矩阵的最低覆盖，不是对能力规格的替代。

| 场景 | 操作与可观察断言 |
|---|---|
| ASR 时延恰为/超过 15 秒 | 注入单调时钟队列：15000ms 不跳读；15001ms 只插入一个居中 `...`，GAP 区间、原因、模型和音频 offset 完整，AAC 无缺口 |
| 跳读后旧结果迟到 | 使旧世代 FINAL 在跳读后返回；不得覆盖 GAP 或重复追加，新世代只处理跳读终点后的 PCM |
| GAP 离线重识别成功 | 断网，用会话固定模型重放跳过区间；新增不可变版本，旧 GAP 可查，仅成功提交后默认文字替换 `...`，下游按新源执行 |
| 重识别失败/取消/模型不可用 | 分别注入失败；原 GAP 或原默认文字不变，无远端请求、无第二模型、无自动批量补转写，可再次手动重试 |
| 普通文字段重识别与用户版本 | 重识别新增 L0 不覆盖用户 L1；版本历史、展示层级和下游依赖可区分 |
| 自动块边界占位竞争 | 在占位事务、编码器初始化和恢复分发处注入故障/重复命令；`(sessionId,chunkSeq)` 唯一，无编码器先于占位，无双活动 writer |
| 有界队列在 BLOCKED 时填满 | 不扩容、不静默丢音频；进入明确失败并记录未能持久化区间，不能显示正常录音 |
| SEALING 与 SEAL_FAILED | `SEALING` 禁止重新打开；仅在旧 PCM 入账、writer 关闭和资源世代有效时走新占位续录，资源失效时停止 |
| 各状态崩溃恢复 | 分别在 `PLACEHOLDER/OPEN/SEALING/SEAL_FAILED` 崩溃；恢复只补交可验证 `SEALED`，其余为 `RECOVERABLE/CORRUPT`，序号不复用 |
| 低存储停止 | 在硬下限触发后确认先 `BLOCKED`/切断点，再封存和冲刷，最后才显示低存储暂停；全程无下一块占位、无旧音频自动删除 |
| 封存失败与空间恢复 | 注入 `SEAL_FAILED` 后不得伪装暂停或继续；空间恢复也等待用户显式继续，并从新占位开始 |
| 暂停与跳读时间映射 | 制造暂停间隙和 ASR 跳读；实际采集 offset 排除暂停但包含已录音的 GAP，回听/导出定位准确 |
| 多 FINAL 折叠与配置变化 | 验证 `foldDueAt` 取最大 `finalizedAt`；只重算未到期段，已到期段不重置，GAP 不自动折叠 |
| 多源响应乱序/缺项/换版 | 响应、缓存和提交三个边界均拒绝；单个源变化使整个产物失效，不部分提交 |
| ReaderContext 生命周期 | 三页切换和页面重建保留锁/锚点；换会话与进程重启清除，持久化 `foldDueAt` 不变 |
| 标题未展示时连续更新 | 最新有效版本继承 `pendingFirstReveal`，只首次实际可见动画一次；revealed 后更新不重置资格 |
| HTTPS 与重定向 | HTTPS 降级被拒绝；跨源 301/302/307/308 均不转发 `Authorization`/Cookie，不自动重放文字正文，新源须重新确认 |
| 模型租约删除与重启 | 活动会话或重识别持租约时删除仅进入 `pending-delete`；重启恢复租约，最后释放前工件可校验且不可物理删除 |
| 工件溯源缺失或不一致 | 不把上游声明当本地验证；哈希、revision、转换配置或许可无法验证时不得标为已验证安装 |

### 完整故障矩阵最低范围

每个场景都必须记录设备、模型/工件版本、队列与资源世代、块状态、实际损失区间、可见错误和恢复结果。下表按“触发 → 必须结果”定义出口，任一单元不得用通用降级说明替代测试。

| 故障类别 | 必测触发 | 必须结果 |
|---|---|---|
| 权限/服务 | 未授权、启动拒绝、录音中撤权、后台启动条件变化 | 不伪装录音；停止新采集，已存证据可读，通知/UI 状态真实 |
| 麦克风 | 占用、AudioRecord 读取错误、设备路由变化、时间戳断裂 | 不静默补零或重用时间；量化影响区间并进入可恢复或失败态 |
| 采集队列 | ASR 慢、AAC 慢、持久化慢、`BLOCKED` 耗尽余量 | 队列有界；ASR 慢走 GAP，音频路径不能保存时停止而非丢音频 |
| 块占位 | 唯一序号冲突、DB 提交失败、临时路径失败、重复命令 | 编码器不得先初始化，无新 PCM 分发，无重复活动块 |
| 编码/封装 | 初始化失败、写入失败、192kbps 不支持、muxer flush/改名失败 | 记录实际参数和 `SEAL_FAILED`；不虚标、不继续伪装保存 |
| 进程/系统 | 各块状态杀进程、服务被杀、设备重启、目录同步交错 | 可恢复提交或明确 `RECOVERABLE/CORRUPT`；不自动无感重启麦克风 |
| 存储 | 预警、正常封存预留不足、硬下限、冲刷失败、空间恢复 | 严格停止顺序、不自动删旧内容、不自动继续、实际边界可见 |
| ASR | 15 秒过载、连续过载、旧事件迟到、推理崩溃、空/无效结果 | GAP 不重复且可回听；后续识别恢复；无自动补转写，失败不覆盖证据 |
| 重识别 | 离线成功、重复点击、取消、模型缺失、租约失败、块未封存/损坏 | 单任务幂等；成功新版本才生效，失败保留原展示，不替换模型 |
| 模型生命周期 | 下载中断、哈希错误、溯源缺失、更新/回滚、租约中删除、崩溃清理 | 原子安装；会话固定版本；`pending-delete` 不提前删文件 |
| BYOK 网络 | 断网、DNS/TLS 失败、超时、401/403、429、5xx、用户取消 | 有界退避，不阻塞音频/ASR；鉴权错误不盲重试，秘密不入日志 |
| BYOK 重定向 | 同源、跨源、HTTPS 降级、循环/超次数、307/308 正文重放 | 凭据不跨源，文字不发往未确认新源，预算耗尽明确失败 |
| BYOK 内容 | 无效 JSON、schema 不符、乱序/缺项源回显、越界引用、无来源事实 | 客户端拒绝，有限修复后回退低层，不部分提交 |
| 任务/缓存 | 重启重复投递、哈希相同列表不同、单源换版、迟到结果 | 逐项源校验与幂等，不重复追加、不覆盖用户版本 |
| 折叠/阅读 | 配置变化、到期无 L2、自由阅读、换会话、进程重启 | 到期规则稳定、锚点正确、ReaderContext 按边界清除 |
| 标题 | 不可见生成、动画中离开/重启、未 revealed 连续更新、旧源晚到 | 最新有效版本继承资格；完成后仅一次；revealed 后普通更新 |
| 回听/导出 | 跨块、GAP、暂停间隙、损坏块、取消、目标空间不足 | 不错误寻址、不将半成品标成功、不删除源块 |
| 删除 | 历史会话、活动会话、任务进行中、共享模型有租约 | 活动会话先封存；共享模型按租约保护，不误删其他会话 |

### 文档校验边界

统一使用固定版本 `@fission-ai/openspec@1.16.1` 执行严格校验，禁止用 `@latest` 让同一报告随时间指向不同 CLI。`docs/validation-report.md` 只记录其所述时点的文档结构、数量与链接检查；本轮修订后严格结构校验已通过，但这不证明技术可实施、真机性能达标、语义质量通过或功能已发布。预注册冻结、技术尖刺与实现验收仍须独立完成。

## Risks

| 风险 | 应对 |
|---|---|
| X-ASR 实机延迟、语义正确性或功耗不达标 | 先冻结基线；正确性门槛不可为速度让步；调整线程/模型块长后重测，必要时回到模型评审，不静默换远端 ASR |
| ASR 过载导致文字缺口 | 15 秒显式 GAP、完整音频保留、逐段手动同模型重识别；不自动补转写 |
| 块切换竞争导致音频或序号丢失 | `BLOCKED` 切点、唯一 `PLACEHOLDER`、资源世代、预留空间和恢复扫描 |
| 设备不支持目标 AAC 参数 | 记录实际编码参数并提示；禁止伪造 192kbps 标记 |
| 分块损坏导致尾部缺失 | 状态化封存、可量化恢复；比较 30/60/300 秒，异常不默认豁免 |
| 工件或许可来源不清 | 不可变 revision、上游/本地哈希分栏、转换配置留痕、未验证不安装 |
| 后台生成迟到导致突然折叠 | FINAL 计时规则固定；配置只重算未到期段；手动展开锁定；锚点与可打断动画 |
| BYOK 兼容性差异或重定向泄密 | HTTPS、能力探测、严格 JSON、跨源不转发凭据/正文、超时/取消和明确错误分类 |
| 多源结果错绑或缓存污染 | 有序 `sourceVersions[]`、规范 `sourceSetHash`、响应/缓存/提交逐项检查 |
| 模型更新/删除破坏会话或重识别 | 会话固定版本、持久化租约、`pending-delete` 与重启恢复 |
| 摘要或纠错漂移 | 原始证据不可变、结构化操作、引用验证、用户版本优先 |
| Flutter 插件长时行为不一致 | 核心音频/ASR 原生薄层；其他包做双参考设备验证并可替换 |
